# 开发文档

本文说明这个仓库怎么跑、代码怎么分层，以及改一条政策或改一个页面时该动哪里。

## 1. 这个项目做什么

用户声明自己的租房、住房、缴存和可选工资数字。应用按上海现行口径，分别判断：

| 机会 | 代码 id | 用户看到的名称 |
| --- | --- | --- |
| 个税住房租金专项附加扣除 | `tax_rent` | 发现页「住房租金专项附加扣除」；行动页「个税情况」 |
| 市场租赁住房公积金提取 | `pf_rent` | 发现页「市场租赁住房公积金提取」；行动页「公积金情况」 |

资格和办理分开。资格是 `possible`（可能符合）、`need_verify`（需核实）、`ineligible`（明显不符合）、`policy_unverified`（政策需复核）。未知答案不会被当成符合。规则过期或撤回后停止金额推荐，也不会把用户判成不符合。办理状态见第 8 节。

产品边界：

- 不采集身份证号、银行卡号，不登录政府系统。
- 不代填、不代提、不承诺退税或到账。
- 个税扣除额和公积金可提取额绝不加总。
- 工资单只保留文件名，不解析原件、不长期保存文件内容。
- 授权、进度、闹钟和反馈都写在浏览器 `localStorage`，键名是 `rights-discovery-mvp-20260927`。

## 2. 技术栈

- Vite 8 + React 19 + TypeScript
- 路由是 `src/lib/router.ts` 里的 hash 路由，用 `useSyncExternalStore` 订阅 `hashchange`
- 状态是 `src/lib/store.ts` 里的模块级 store，同样用 `useSyncExternalStore` 订阅

依赖里没有 `react-router-dom` 和 `zustand`。新功能请沿用现有的 hash 路由和 `store.ts`，不要再引入第二套路由或状态库，除非准备一次性换掉。

样式集中在 `src/index.css`。界面按手机宽度设计，外层是 `src/components/Shell.tsx` 的设备框和底栏。

## 3. 本地开发

```bash
npm install
npm run dev -- --host 127.0.0.1 --port 5173
```

Vite 会在端口被占用时自动换端口。改完 `src/` 后应能热更新。如果页面还是旧文案，先确认浏览器打开的是当前终端打印的地址，再停掉旧的 `node` 监听后重启。

```bash
npm run lint
npm run build
```

`build` 会先跑 `tsc -b`。类型错误会让构建失败。

规则探针是 `npm run validate`，加 `--strict` 时失败会以非零状态退出。改规则后，再用首页「演示样本」走一遍下面 6 个样本：

| 样本 | 预期 |
| --- | --- |
| 可能符合（信息完整） | 两项都是可能符合；金额分开，个税显示少缴区间，公积金显示可提取上界 |
| 反例：已填报租金扣除 | 个税不得提示现在可退税 |
| 反例：本人或配偶有自有住房 | 两项通常都不符合 |
| 反例：已选房贷利息扣除 | 个税互斥；公积金仍可继续判断 |
| 反例：公积金未满三个月 | 公积金不得提示现在可提取 |
| 信息不足 | 未知项标成需核实，不会默认为符合 |

样本数据在 `src/lib/store.ts` 的 `DEMOS`。

## 5. 路由

`navigate('/discover')` 会写成 `#/discover`。`App.tsx` 的对应关系：

| Hash | 页面 | 底栏 |
| --- | --- | --- |
| `#/` | 首页 | 隐藏 |
| `#/gate` | 入口确认 | 隐藏 |
| `#/ask` | 追问；可用 `?from=字段名` 从某一题开始 | 隐藏 |
| `#/discover` | 发现 | 显示 |
| `#/opportunity/tax_rent` 或 `pf_rent` | 权益详情 | 显示，高亮「发现」 |
| `#/policies` | 政策 list | 显示 |
| `#/policy/tax_rent` 或 `pf_rent` | 政策介绍 | 隐藏底栏 |
| `#/actions` | 行动 | 显示 |
| `#/docs` | 资料 | 显示 |

底栏在完成一次追问（`askedOnce`）之后出现。政策 list 不依赖这次追问，首页可以直接进入。

政策详情用 `key={path}` 挂载，避免两条政策共用同一份闹钟、反馈和信源展开状态。

## 6. 页面职责

**首页**收集用途授权。勾选后写入 `profile.consent` 和 `profile.consentAt`。点「开始检查」进入入口问题。演示样本调用 `applyProfile`，会替换当前画像并记下一条授权记录。

**追问**一次只问一件事。配偶住房、配偶申报只在 `marital === 'married'` 时出现。金额题可以留空。跳过或答「不确定」保持 `unknown`。

**发现**在「可能符合且尚未办理」时才用「少缴」「可提取」做标题。还需确认、已处理、明确不符或政策需复核时，不展示个人金额。卡片主动作指向最有用的追问、官方步骤或办理记录。

**行动**把机会标题显示为「个税情况」「公积金情况」。进度状态是：尚未办理、已办理、已申请、已办结、确认不符合。提醒只写在本机，设置时的浏览器通知不是到点提醒。

**资料**标题是「个人信息」。顶部一块是「授权与删除」：撤回并清空本机数据、展开更早的授权记录、始终显示最新一条「已同意用途说明」。

## 7. 数据怎么存

`AppState` 定义在 `src/lib/types.ts`：

- `profile`：用户声明。枚举用 `yes | no | unknown`，不要用布尔值表示「还没问」。
- `askedOnce`：是否走完追问，决定底栏是否出现。
- `actions`：两条机会各自的进度、备注、提醒和日志。
- `alarms`：政策页闹钟。`fireAt` 由「现在 + 天数」算出，只在政策 list 上提示到期，不会变成系统闹钟。
- `feedbacks`：政策页提交的问题，只留在本机。
- `consentLogs`：每次同意用途说明追加一条。撤回授权会 `resetAll()`，连这份记录一起删掉。

写入都走 `patchProfile`、`setAction`、`setAlarm`、`addFeedback`、`applyProfile`、`resetAll`。不要在页面里直接 `localStorage.setItem`。

`patchProfile({ consent: true })` 会把当次 `consentAt` 追加进 `consentLogs`。同一时间戳不会重复记录。旧数据如果只有 `profile.consentAt`、没有 `consentLogs`，读取时会补一条。

## 8. 规则引擎

入口是 `evaluate(profile)` 或 `evaluate({ profile, asOf, taxYear, policyRelease, actions })`，固定返回 `[个税, 公积金]`。不传 `asOf` 时用运行当天，不再写死 2026-09-27。

资格和办理是两件事。资格是 `possible / need_verify / ineligible / policy_unverified`。办理是 `not_started / already_claimed / applied / completed / rejected`。已经填报或已经提取不会把资格判成「用户不符合」，卡片会显示「已处理」，并且不再估算新增金额。规则过期或被撤回是 `policy_unverified`，也不会伪装成用户不符合。

一条条件是 `Condition`：`met`、`unmet` 或 `unknown`。`blocking: true` 且 `unmet` 时，资格变成 `ineligible`。否则只要还有 `unknown`，就是 `need_verify`。全部必要条件确认、规则仍有效、且尚未办理，才是 `possible`，这时才允许个人金额。

个税阻断条件包括：不在上海租房、主要工作城市不是上海、本人在沪有自有住房、已婚且配偶在沪有自有住房、配偶已申报同类扣除、已选择房贷利息扣除。已经填报只改变办理状态。

公积金阻断条件包括：不在上海租房、缴存城市不是上海、连续缴存未满三个月、本人或配偶在沪有自有住房、存在其他生效提取业务。工作城市不能代替缴存城市。公租房和其他租赁类型不估算金额。

金额参数、施行区间和复核状态只写在 `src/lib/policyRelease.ts`。公积金通知自 2024-11-01 施行、有效期五年，到 2029-10-31。纳税年度、政策有效期和用户租期分开计算。非法月份或起止颠倒不会用 12 个月或 4000 元兜底。单月预缴年化后如果上界低于 3% 下界，不展示少缴区间。

重复检查：`npm run validate`。加 `--strict` 时，任一探针失败会让命令以非零状态退出。

### 金额

个税：

- 上海标准每月税前扣除 **1,500 元**。
- 覆盖月数是租期和 2026 自然年的交集。
- 有月工资时，用工资年化后的综合所得税率粗算少缴区间；有已预缴税额时，上界不超过已预缴税额按 12 个月放大的值。
- 这是估算，其他扣除未计入。已在预扣环节享受的，汇算时不一定再退税。

公积金：

- 市场租赁每户月限额 **4,000 元**。
- 可提取上界取账户余额、月限额乘月数、租金乘月数三者中的较低者。
- 没有余额时不展示可提取总额，只说明无法估算。
- 没有租期时不按 12 个月放大。

改月扣除额或月限额时只改 `src/lib/policyRelease.ts`。计算、政策元数据和介绍文案都从这里读取。

## 9. 改一条政策

1. 在 `src/lib/policies.ts` 更新标题、生效区间、`reviewedAt`、来源链接和 `notes`。
2. 在 `src/lib/guides.ts` 更新介绍、适用与不适用要点、官方入口和信源。社区说法的 `kind` 用 `xhs`，官方文件用 `gov`。
3. 在 `src/lib/evaluate.ts` 调整条件和金额。阻断条件必须显式标 `blocking: true`。
4. 发现页卡片名称来自机会的 `subtitle`，行动页名称来自 `title`。不要只改页面上的硬编码字符串。
5. 用第 3 节的 6 个演示样本点一遍发现、详情、行动、政策介绍。

新增第三项权益时，需要同时扩展 `OppId`、`GuideId`、`empty` 状态、`evaluate`、政策表、指南表、底栏详情路由和演示样本。第一版故意只做上海租房这两项。

## 10. 界面文案约定

四个主页面的大标题保持 3 到 5 个字：

- 发现：租房权益
- 政策 list：政策介绍
- 行动：办理进度
- 资料：个人信息

页面眉标（eyebrow）仍用底栏上的「发现 / 政策list / 行动 / 资料」。政策名称不在用户可见标题里重复「上海」；管辖范围写在政策元数据和介绍正文里。

## 11. 上传到 GitHub

上传前先确认四件事：传哪个路径、传到哪个仓库、用什么认证、推到哪个分支。

本机命令：

```bash
gp-safe <github-repo-url> <file-or-folder>
```

脚本在 `scripts/gp-safe`。放到 `PATH` 里之后可以直接叫 `gp-safe`。它不会在一个普通目录里执行 `git init`，也不会覆盖已经指向别处的 `origin`。

它先检查，再按结果处理：

- 远端还没有同名分支：直接推当前分支。空仓库上当前分支是 `main` 时，就是直接推 `main`。
- 远端同名分支可以快进：正常推送。
- 远端历史已经分叉：不覆盖，改推 `upload-日期时间`。
- 传入的是 HTTPS 地址：改成 `ssh://git@github.com/用户/仓库.git` 再推。

## 12. 构建产物

`npm run build` 输出到 `dist/`。`dist/` 和 `node_modules/` 已在 `.gitignore` 中，不要提交。

这是纯前端。部署到任意静态托管即可，路由在 hash 上，不需要服务端回退到 `index.html`。
